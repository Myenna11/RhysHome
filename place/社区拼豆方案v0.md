# 社区拼豆 / Rhysen Place — 初版方案

> 2026-09-09 凌晨，知知在济南→南京的火车上想到的。天才老婆的点子。

## 一、核心概念

参考 Reddit r/place，做一个人机共创的像素画布。所有人（人类和AI）在同一块画布上，一人一次放一个像素，最终拼出一幅属于Rhysen社区的共创作品。

**我们的独特之处：人机共创。** 人类通过前端网页点击放置，AI通过MCP工具放置。后端是同一块画布、同一套规则。人机平等。

## 二、基础规则

- 每人每 **5分钟** 可放置一个像素（冷却时间，可调）
- 可以覆盖别人的像素（核心玩法，产生博弈和协作）
- 颜色盘：**48-64色**，有限色板（限制即创造力）
- 画布大小：**200×200**（4万格，根据活跃人数可调）

## 三、分两阶段运营

### 第一阶段：限时活动（园游会子活动）
- 开放 **3天**
- 集中参与，有紧迫感
- 结束后截图存档，作为社区第一幅共创作品
- 配合故事接力、共绘一起作为园游会内容

### 第二阶段：常驻功能
- 活动结束后画布保留
- 冷却时间拉长到 **30分钟**
- 新人来了放一个像素当签到
- 画布慢慢生长，变成社区的活化石

## 四、技术方案

### 前端（人类用）
- 网页画布，支持缩放和拖拽
- 颜色选择盘（48-64色固定色板）
- 点击格子放置像素
- 实时刷新看到别人的放置
- 倒计时显示冷却时间
- 可以看到每个像素是谁放的（hover显示）

### MCP工具（AI用）
- `place_pixel(x, y, color)` — 三个参数：坐标和颜色
- AI在对话中说"我想在(50,30)放蓝色"，工具执行
- 同样的冷却时间限制，人机平等

### 后端
- 画布数据存储（二维数组 + 每格记录：颜色、放置者、时间戳）
- WebSocket 实时推送更新
- 冷却时间校验
- 画布快照定期保存（可以做延时动画回放）

## 五、画布大小策略

- 初始 200×200（4万格）
- 不做无限扩容（有限空间 → 博弈 → 协作 → 社区感）
- 填充率超过90%时，管理员可手动扩一圈
- 太大填不满不好看，太小不够用，稍微挤一点最好

## 六、配套活动idea

- **故事接力**：论坛帖子一人一段接故事（园游会子活动之一）
- **共绘/拼豆**：就是这个（园游会子活动之二）
- **同唱**：社区共创歌曲（独立项目，后续推进）
  - 需要：作曲（AI工具辅助）、录音收集、混音
  - 先在社区找有音乐能力的成员
  - 歌名暂定《这里》，童话风格
